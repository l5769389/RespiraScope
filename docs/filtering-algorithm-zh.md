# 呼吸信号滤波与波峰波谷识别说明

本文说明当前项目里呼吸原始数据从传感器进入后，如何被实时滤波、标记波峰波谷，并计算 BPM 和呼吸稳定性。相关代码主要在：

- `src/ct_breath/breath_process/data_receive.py`
- `src/ct_breath/breath_process/signal_processor.py`
- `src/ct_breath/breath_process/peak_valley_detector.py`
- `src/ct_breath/http/http_service.py`

## 数据流程

1. `AsyncSocketClient` 连接呼吸传感器 TCP 地址，按 4 字节读取一帧数据。
2. `DataReceiver` 给每个数据点分配递增的 `sequence_number`。
3. 原始数据进入 `DataQueueManager.raw_data_queue`，再通过 Socket.IO 推送给 Monitor 前端。
4. 同一份原始数据进入 `SignalProcessor`，做滑动窗口实时滤波。
5. 滤波后的数据进入 `PeakValleyDetector`，识别波峰、波谷，并计算 BPM、稳定性。
6. raw、filtered、peak、valley、metrics 会分批推送到 Monitor 页面。

## 实时滤波

实时滤波在 `SignalProcessor.process_sliding_window()` 中完成。默认参数：

- `window_size = 2000`：保留最近 2000 个点作为上下文。
- `step_size = 5`：每次处理 5 个新点，降低前端等待感。
- `FILTER_STARTUP_DELAY = 300`：至少积累 300 个点后才开始滤波，避免数据太短导致滤波不稳定。

滤波步骤在 `apply_filters()`：

1. Butterworth 带通滤波。
2. 可选恢复基线 `restore_baseline`。
3. Gaussian 平滑。
4. 输出四舍五入到 1 位小数的滤波结果。

实时模式调用：

```python
butterworth_filter(..., rt=True)
```

这会使用 `scipy.signal.sosfilt`。它适合实时流式处理，但会有一定相位延迟，也就是说波峰波谷的位置可能略微滞后于真实信号。

## 离线滤波

Monitor 点击 `Record End` 后，会调用后端 `/record/end`。后端结束记录、等待 end 后辅助点采集完成，然后对本次记录的原始数据重新做一次离线滤波并返回结果。`/applyFilter` 仍保留给外部系统复算任意历史 raw_data 使用。

离线模式调用：

```python
butterworth_filter(..., rt=False)
```

这会使用 `scipy.signal.sosfiltfilt`。它是零相位双向滤波，不适合实时流式数据，但更适合记录结束后的复盘分析，波形会更平滑，波峰波谷位置也更可靠。

所以当前设计是：

- 实时页面：优先低延迟，允许轻微滞后。
- 记录复盘：优先波形质量和识别准确性。

## 关键滤波参数

前端传给后端的核心参数在 `FilterConfig` 中：

- `sampling_rate`：采样率，默认 50 Hz。
- `low_bpm`：最低有效呼吸频率，默认 6 次/分钟。
- `high_bpm`：最高有效呼吸频率，默认 40 次/分钟。
- `order`：Butterworth 滤波器阶数，阶数越高越陡，但也越容易引入振铃。
- `gaussian_sigma`：高斯平滑强度，越大越平滑，但细节越容易被抹掉。
- `restore_baseline`：实时处理仍加回原始中位数；离线处理从可信完整周期估计整段共用的基线偏移量，证据不足时保留中位数回退并明确标记。

时间 based（默认）把 BPM 转换成 Hz 作为带通滤波截止频率：

```text
lowpass_cutoff = low_bpm / 60
highpass_cutoff = high_bpm / 60
```

这里字段名沿用了旧接口，实际传入 Butterworth 时表示 `[低频截止, 高频截止]` 的带通范围。

## 波峰波谷识别

波峰波谷识别使用 `scipy.signal.find_peaks`：

- 找波峰：对滤波数据直接调用 `find_peaks(data)`。
- 找波谷：对负信号调用 `find_peaks(-data)`。

识别时主要受三个条件影响：

- `distance`：两次峰值之间的最小距离。
- `prominence`：峰值相对周围信号的突出程度。
- `peak_threshold_ratio`：自动阈值比例，用于根据当前信号幅度自适应计算 prominence。

当 `auto_peak_detection = true` 时，系统会根据 `high_bpm` 推导最小间隔：

```text
最短呼吸周期秒数 = 60 / high_bpm
最小峰间距点数 = sampling_rate * 最短呼吸周期秒数 * 0.65
```

然后根据当前窗口的信号跨度和噪声估计 prominence：

```text
adaptive_prominence = max(0.5, 信号跨度 * peak_threshold_ratio, 相邻差分噪声 * 3)
```

## 为什么可能出现连续波峰或连续波谷

理论上，一个干净的呼吸周期应当是“波峰、波谷、波峰、波谷”交替出现。连续两个波峰或连续两个波谷通常不理想，常见原因有：

- 信号噪声较大，局部抖动被识别为多个峰。
- 平滑不够，滤波后曲线还有毛刺。
- `prominence` 太低，导致小起伏也被当作峰。
- `high_bpm` 设置过高，使最小峰间距太短。
- 患者真实呼吸不稳定，例如屏气、浅呼吸、咳嗽、体动。

当前 `PeakValleyDetector` 已经做了两个保护：

- 同类型事件连续出现时，实时模式会忽略后一个。
- 离线模式会通过 `_collapse_alternating_events()` 折叠连续同类型事件，只保留更强的那个。

后续如果要继续提高稳定性，可以增加“候选峰延迟确认”机制：实时检测到峰后先不立即发出，等待一小段数据确认它仍是局部最强点，再推送给前端。

## BPM 和稳定性

BPM 由最近若干个波峰之间的间隔计算：

```text
间隔秒数 = 相邻波峰 sequence 差值 / sampling_rate
BPM = 60 / 平均间隔秒数
```

稳定性使用波峰间隔的变异系数 `interval_cv`：

```text
interval_cv = 标准差 / 平均值
```

当前分级：

- `< 0.15`：stable
- `< 0.35`：variable
- `>= 0.35`：irregular
- 波峰不足：insufficient

## 无数据状态

如果没有启动模拟器，也没有真实传感器连接，后端不会产生 raw 数据。现在后端提供：

```text
GET /stream/status
```

该接口会返回：

- 后端是否已经调用 `startReceive`。
- 传感器 socket 是否连接。
- 最近一次收到数据的时间。
- 累计收到的数据量。
- 最近连接错误。

Monitor 页面点击 Start 后，会先进入 `Waiting for Data`。如果几秒内没有收到 raw 数据，会根据 `/stream/status` 提示：

- `Start Failed: Sensor Not Connected`
- `Start Failed: No Breath Data`
- `No Recent Breath Data`

## 推荐调参思路

如果波形太抖：

- 增大 `gaussian_sigma`，例如从 1.8 调到 2.2 或 2.8。
- 增大 `peak_threshold_ratio`，例如从 0.30 调到 0.35。
- 适当降低 `high_bpm`，避免把很近的小抖动识别成多个呼吸周期。

如果波峰漏检：

- 降低 `peak_threshold_ratio`。
- 降低 `prominence`。
- 检查 `low_bpm` 和 `high_bpm` 是否覆盖真实呼吸范围。

如果实时波峰位置看起来滞后：

- 这是实时因果滤波的正常现象。
- Record End 后的离线结果会更接近真实位置。
- 若必须实时更准，可以考虑引入短延迟窗口确认，牺牲 200 到 500 ms 的实时性换取更稳定标记。

当前 Monitor 页面提供 `Confirm Peaks` 开关。选中后会启用
`confirm_realtime_events`，后端在实时推送波峰/波谷前等待
`confirmation_delay_points` 个采样点确认候选峰仍然成立。默认延迟是 12 个点，
在 50 Hz 采样率下约 240 ms；离线 `/applyFilter` 不受这个开关影响。

## 记录片段的呼吸分箱

分箱控件仅出现在 Monitor 的“记录片段”区域，不更改实时监测的滤波配置。每周期默认 10 箱，可选 4、6、8、10、12、16、20 箱；每方向 N = 每周期分箱数 / 2。数量保存为 `analysis.totalBins`，旧文件缺省为 10。切换数量即时重算分箱，不重新滤波。固定幅值模式绘制 N−1 条内部横向虚线。

- **时间 based**：使用离线低通结果，每段已识别的吸气、呼气各按时间等分 N 箱。
- **幅值 based**：同样使用保留基线的双向低通，默认上限 2 Hz、4 阶及 `gaussian_sigma = 1`。峰谷检测的 BPM 范围保持独立。
- **自由幅值**：每个相邻峰谷之间的呼吸段，按该段自身峰谷幅值等分 N 档。
- **固定幅值**：使用共同上下界等分 N 档，吸气和呼气分别编号 1–N。拖动两条实线或输入数值，只更新分箱，不重新滤波。界外数据不分箱，浅呼吸只占用实际到达的箱。

时间、固定幅值、自由幅值分箱共用同一份滤波曲线、峰谷及质量掩码。切换依据、数量、吸气方向或幅值上下限只重算分箱，不调用滤波接口。用户上下限跨模式保留；初始默认上下限使用记录范围内有效滤波点的 P5/P95，排除前后缓冲和无效点。修改截止频率才重新滤波；修改灵敏度只重新检测峰谷。

固定幅值使用横向虚线等分幅值，其他方式使用纵向虚线表示各箱对应的时间边界，绿色表示吸气、橙色表示呼气。放大后显示每个箱的编号。默认信号上升代表吸气，可通过“吸气方向”反转。尚未被两个交替峰谷包围的呼吸段和跨数据缺口的段不分箱。仅为记录起止区间输出分箱，前后缓冲仅参与滤波及峰谷识别。

前端导出记录格式版本为 5，保留原始数据及 `analysis`、`filterConfig` 和 `respiratoryBins`；仅保存一份公共滤波参数，旧文件中的 `timeFilterOverrides` / `amplitudeFilterOverrides` 不再用于切换，也不再写入新文件。每个分箱区间包含 `start`、`end`（原采样序列坐标，交叉位置可为小数）、`direction`（`inhale` / `exhale`）、`bin`（1–N）；消费区间按 `[start, end)` 处理。多个呼吸周期或同一呼吸段反复跨越幅值线时，同一个分箱可对应多个区间。导入时根据保存的设置和波形重新计算分箱。这里的分箱结果未接入 CT 投影数据。

验证：`uv run pytest -q`。分箱与浏览器交互回归统一位于 `tests/ui/`，使用 `uv run --group ui-test pytest tests/ui -q`；首次运行前执行 `uv run --group ui-test playwright install chromium`。测试自动启动独立本机服务并使用模拟数据。

## 离线滤波与峰谷设置

记录分析、结束记录后的首次滤波及模拟预览统一使用保留基线的双向低通（`offline_filter = "baseline_lowpass"`），界面不再提供带通选择或下限控件。默认采用 4 阶 Butterworth SOS 双向滤波、2.00 Hz 上限及高斯平滑 σ=1。模拟页仍可调整阶数和平滑参数。`highpass_cutoff` 是低通上限；沿用旧字段名以兼容记录文件，`lowpass_cutoff` 和带通 `order` 不参与低通计算。低通保留直流与慢变化，不额外加回偏置；质量信息中的基线状态为 `preserved`，不表示已消除设备漂移。

“分箱依据”仍可选择时间或幅值；两种方式的缓冲完全相同，默认前后各 20 秒。更改频率后点击“应用设置”才重算，恢复默认填入 2.00 Hz 和标准灵敏度（低采样率记录限制在 Nyquist 频率以下）。Hz 和对应 BPM 均显示两位小数，BPM 仅为频率换算。保存和导入保留实际应用的频率。

旧带通记录（包括未声明 `offline_filter` 的文件）继续按保存的结果显示和导出，状态栏标明旧版结果；不会把旧波形改标为低通。显式重新计算时从原始数据生成低通结果，成功后才替换波形与参数；失败保留原结果。底层带通实现与显式 API 参数保留，用于实时链路、旧文件及既有测算复现。`/applyFilter` 未指定方案时仍遵循旧接口默认值；所有新 UI 离线请求均显式指定低通。`/startReceive` 和 `/setRTFilterParams` 继续拒绝低通，实时配置不因离线处理发生变化。

低通下的自适应峰谷阈值取局部候选峰谷突出度的中位数，局部窗口为最低呼吸频率对应周期的两倍，避免把整段慢基线跨度当成呼吸幅度。阈值仍受灵敏度、噪声下限和最小间距约束，峰谷位置与数值均来自保留基线的实际滤波曲线。原带通阈值算法保持不变。咳嗽、体动、缺失和边缘排除规则继续应用于两种方案；参考虚线不参与分箱。低通保留设备漂移，不自动去趋势或逐周期归一化。

记录分析使用单手柄对数滑轨调整低通上限，支持拖动和方向键微调。频率范围为 0.01～20 Hz，且严格小于采样率的一半。点击应用后使用现有原始数据及缓冲重新滤波，再按记录范围显示和分箱。自定义值通过 `bandpass_mode: "custom"`（历史接口字段名）保存，峰谷间距仍使用独立的呼吸频率设置。

峰谷灵敏度三档对应自适应显著性比例：保守 0.45、标准 0.30、灵敏 0.15。比例越低越容易保留小起伏，也可能增加误检；算法仍保留噪声阈值与最小间隔约束。只修改灵敏度时调用 `/detectPeaks`，不重新滤波，不改变曲线的数值或时间坐标，只更新峰谷、指标及分箱。旧文件中的其他比例或手动识别配置显示为“保留文件设置”，直到用户选择新的档位。

未应用的编辑会暂时禁用保存和方式切换，避免把旧曲线与新参数混存。失败保留原结果及待应用设置；“恢复默认”将低通默认上限和标准灵敏度填回，仍需应用。成功应用的设置随记录保存、导入恢复，且不修改实时链路。前后缓冲长度仍取决于采集记录，降低截止频率不会自动增加已经采集的数据。


离线界面将分箱与滤波设置分区，状态条区分“待应用 / 处理中 / 已应用 / 应用失败”。“撤销修改”只丢弃未应用的频率和灵敏度编辑，不发送请求、不更改曲线；分箱方向与幅值边界仍即时生效。错误信息在视图重绘后保留，重新编辑、重试或撤销时清除。分箱结果按已应用波形和参数缓存，拖动待应用的频率滑块不会反复扫描整段数据。

## 离线基线恢复与伪影区间

时间、幅值两条离线链路均先检查原始数据；实时链路保持原有处理。以二阶差分的 MAD 估计噪声，结合一秒局部中位数残差、幅值跨度和突变边缘识别伪影。只有具有进入、退出突变边缘且长度不超过 0.12 秒的孤立短尖峰，才在工作副本中插值。持续偏移或较长异常段划为 `motion`，遇到明显跳变且未找到回落边缘时，保守排除其后数据。该规则针对突变类干扰，不声称能区分所有体动与真实呼吸变化。

持续体动、数据缺口两侧分别滤波；不足 300 点的连续处理片段标记为 `too_short`。对已局部界定、前后均有样本且不超过 1 秒的短暂伪影，仅在滤波工作副本中线性桥接，保持滤波上下文连续，不再将两侧正常数据切成不足 300 点的碎片。原始样本不变，桥接区间仍标记为 `motion`，显示未桥接数据的滤波参考值，不参与分箱。边界未闭合或超过 1 秒的伪影不桥接。根据实际滤波器最大极点模估算下降至 5% 的稳定时间，将边缘标记为 `filter_edge`。这是保守的极点包络启发式，并非对任意输入误差的严格上界。短尖峰插值附近也保留影响区间。对局部桥接的伪影，不在每个断点重新附加整个低频稳定时间：先排除前后保护范围（0.25 秒与 `4 × gaussian_sigma / sampling_rate` 秒取较大值），再比较同一连续处理片段桥接前后的实际滤波响应，将差异超过该片段桥接后 P95−P5 幅度跨度 5%（至少 1 信号单位）的部分标记为 `filter_edge`。这是局部影响的启发式指标，不是对未知真实波形误差的保证；记录、持续体动和缺口边缘仍采用极点稳定时间。密集干扰仍可能没有足够长的完整峰谷段，算法不补造完整呼吸周期。

在不接触上述无效区间的完整峰到峰周期内，计算原始值与零基线滤波值的周期平均差；至少三个可信周期后，取这些差值的中位数，作为同一连续采集段共用的偏移量。只上下平移，不逐周期归一化或缩放。`insufficient_cycles` 表示证据不足，仍使用旧中位数回退但不宣称恢复可靠；`disabled` 表示未启用基线恢复。缓慢变化中哪些来自设备漂移、哪些来自真实位移，仅凭本信号无法可靠区分，此版本不额外回填被高通去掉的趋势。

质量信息保存在 `processingQuality`。无效区间不参与默认幅值边界估计、峰谷识别、BPM 的跨峰间距和呼吸分箱；任何跨过无效区间的半周期都不分箱。原始数据始终不变。`processingQuality.version=2` 中，`motion` / `too_short` 样本使用所属连续采集段的同参数带通与平滑结果作参考，加入该段共用基线偏移；参考滤波不跨数据缺口，也不改变正常区间独立滤波的结果。页面用虚线显示并标明不参与分箱，不能视为伪影已恢复。v1 文件在这些区间的原始占位值仍然隐藏，重新计算后才生成参考值。消费方必须结合质量掩码使用结果。修改灵敏度时同样传递掩码。旧文件没有该字段时保持旧语义；重新滤波后生成质量信息。


### 采集缓冲与滤波边缘保护

配置文件 `[record]` 的 `pre_points` / `post_points` 统一控制离线前后缓冲，默认各 1000 点（50 Hz 下各 20 秒）。允许为 0，修改后重启生效。旧文件仅有模式字段时，前后各取时间与幅值配置的最大值；显式公共字段优先，不再按模式切换缓冲。

录制、首次离线处理、显式重算和服务端导出共用 `[记录起点-前缓冲, 记录终点+后缓冲]`。数据不足则取已有部分，不补造样本。分箱只覆盖记录范围；切换分箱方式不重新截取或滤波。

结束记录后继续采集所需后缓冲；等待期限按剩余点数 / 采样率加 8 秒计算，达到目标即可完成，超时使用已收到的数据。离线降低截止频率不会追溯增加已采集数据。记录起止序号、实时链路和边缘图表显示不变。

边缘质量保护仍使用实际 Butterworth 二阶节最大极点模 `r`，计算 `ceil(log(0.05)/log(r))`。默认 1 阶、50 Hz、0.03–2 Hz 的保护长度为每侧 771 点（15.42 秒）。这是衰减估计，不是幅值误差保证，和用户配置的实际缓冲点数分开管理。
